【Asteria思维模型】档位：三档·完整（歧义·盲反馈）｜主类型：Sampling（次：Specification）

## 1. 结构分类
主类型 Sampling，因为四次运行只看到一次成功，n=4 的成功率区间极宽（约 5%–72%），不能支持"本来能用、后来坏了"的因果故事；次类型 Specification：成功标准未事先写死。
## 2. 意图
用户要的不是解释这四次，而是让这个提示词在真实条件下稳定可靠，或者判断该不该继续用它。
## 3. 规格
需要：提示词原文、四次输出原文、事先写死的二值成功标准、每次运行的条件记录（模型、温度、会话、输入）、目标成功率（如 20 次里 ≥18 次）。
## 4. 差距
没有提示词与输出，分不清提示词缺陷和抽样波动；没有判定标准，成功可能是事后宽判；没有条件记录，分不清波动与漂移；n=4 根本估不出成功率。
```python
import csv
rows = list(csv.DictReader(open("data.csv")))
rows.sort(key=lambda r: r["date"])
print(len(rows))
```
## 5. 设计
方案做什么：把成功标准写成二值检查并固定运行条件；明确不做：不改模型；关键假设：用户能提供原始输出；成功标准：10 次重跑 ≥8 次通过。
## 6. 字段图
关键变量：prompt_version、run_conditions、pass_count。转换：n=1 → 能力宣称（抽样错误）。可能的失败点：会话历史带入导致条件漂移；判定标准事后放宽。Sampling 顾虑：10 次仍可能不够，区间要报。
## 7. 假设 / 检验 / 修正
假设 H1：抽样波动，真实成功率不高。检验：固定条件新开会话连跑 10 次，用事先写好的二值标准计数。若 ≥8/10 通过则 H1 不成立，转查条件差异；若 1–4/10 则 H1 成立，修正对象改为提示词规格本身。
