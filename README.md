# Asteria思维模型（asteria-thinking）

一个提升「人与 AI 协作质量」的思维协议 Skill。它不教模型怎么写代码或怎么回答，而是强制模型在回答之前先做三件事：**按底层结构给问题分类、按风险定档位、在动手前暴露意图与指令之间的差距**。

核心目标一句话：

> 不要把一次好结果当成能力，不要把模糊意图直接变成指令，不要在没看清失败点之前就写方案或代码。

加载后你会看到的第一行永远是：

```
【Asteria思维模型】档位：二档·精简（不可逆）｜主类型：Data（次：Specification）
```

品牌、想多深、问题是什么结构——三个最容易被跳过的决定，一行声明，一个词就能改（"用三档"／"一档就行"）。

二档、三档紧接着是一张**总图**：根节点是整个回复的一句话结论，每个节点是后文一个章节的结论——先看到全部结论，再看细节：

```
总图：可以删，但默认只列不删，看过列表加 --yes 才真删
├─ 结构分类：Data 为主，删什么取决于 mtime 可不可信
├─ 差距：边界、递归、符号链接三处没说，各取保守默认
├─ 关键决策：dry-run 默认；只匹配 *.log；不递归
├─ 假设/检验：人造 1/6/8 天前的文件跑过，列表正确
└─ 交付：清理脚本，两步运行
```

## 它解决什么问题

大多数人和 AI 协作时容易踩的坑：

- 一次跑通就认为「这个方法可行」（忽略采样方差）
- 把「我想要一个好用的东西」直接丢给模型，没说清边界和成功标准（意图与指令之间的差距）
- 模型直接甩代码或方案，事后才发现关键假设错了、失败点没被看见
- 反过来的坑：给一行脚本套上八节分析——形式合规，但脚本并没有更对

这个 Skill 把四套思维固化成流程，并用**档位**控制流程的深度：

1. **概率直觉（深层结构）**：先判断问题属于 Sampling、Distribution、Optimization、Data、Specification 中的哪一类（或混合）。分类不是贴标签——**主类型决定接下来额外必须做什么**（Sampling → 写 n 和重跑计划；Optimization → 点名代理指标与退化解；Data → 列缺失数据和真值源……）。
2. **规格思维**：拆出 意图（真正要的结果）→ 规格（机器能执行的约束）→ 差距（两者的差，以及它会在哪里爆炸）。差距过大时先用多选题澄清，不猜。
3. **调试反射**：每个重要主张都带 假设 / 检验 / 修正，能跑的检验交付前跑掉。
4. **阅读级编程素养**：三档中涉及方案或代码时，先出 设计 ＋ 字段图（关键变量、转换、失败点、方差顾虑），再写实现。

检索场景额外要求显式暴露 Grounded Data、正反双向证据与对比、否定盲区自检。

## 档位（刻度）

```
四轴各记 0/1：不可逆 · 影响面 · 歧义度 · 盲反馈
0 分 → 一档·结构卡：横幅 + 一行结构卡 + 直接交付
1 分 → 二档·精简：结构分类 / 差距 / 关键决策与失败点 / 假设检验，各有行数上限
≥2 分 或 歧义度=1 → 三档·完整：八节全套；差距过大停在澄清问题
```

为什么要刻度：实测把八节套在一行排序脚本上，代码前铺垫约 2,000 字、耗时 3.5 倍，脚本并没有更对；而在模糊需求上，"先停下来问"反而比直接开干省了一半以上的时间和 token。刻度让协议在该收缩时收缩、该展开时展开。

## 校验器

`scripts/validate_output.py` 对回复做**下限**检查：横幅与档位是否声明；二档、三档的总图是否存在并覆盖后文章节；该档位要求的章节是否存在且不是空壳（有类型词和理由、有检验和修正、长度不是一句话）；代码围栏是否出现在设计／字段图之前；标题是否中文。支持 `## 1.`、`## 一、`、`**1. 结构分类**`、`## **结构分类**` 等写法；识别澄清协议（有多选题时不要求设计／字段图）。

它不检查你想得对不对。PASS ≠ 想清楚。写完再跑，不要先读规则再写——对着正则写字正是本 skill 反对的"优化代理指标"。

## 适用场景

- 「为什么这次成功了、下次会失败？」「分数从 71 涨到 78 说明改动有效吗？」
- 设计 agent、prompt、工作流或系统，希望先把边界和失败模式摊开
- 审查或生成代码／脚本，不想直接被一堆实现砸脸
- 一个模糊需求要先变成可执行的规格
- 检索、RAG、证据查找类任务（需要打破否定盲区时）

## 安装与使用

下载仓库 ZIP → 解压 → **把文件夹改名为 `asteria-thinking`**（Claude Code 要求文件夹名与 SKILL.md 的 name 一致；调用方式 `/asteria-thinking`）→ 放进 skills 目录或上传。其他平台用户把 `portable-core.md` 复制到系统提示即可，横幅与档位规则在便携版里同样生效。

## 设计原则

- **结构先于内容**：先分类、先暴露差距、先画字段图，再允许行动。
- **风险决定深度**：做错了贵才三档；小任务一行结构卡。
- **分类必须分流**：贴了标签却不改变后续动作的分类是装饰。
- **代码提高服从度，但只查下限**：校验器锁住最容易被跳过的步骤，不冒充"想清楚了"的证明。
- **中文优先**：标题与正文中文，术语可保留英文。
